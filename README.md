# Meyers Menu Calendar

Scrapes the weekly Meyers Kantiner lunch menus and serves them as iCal feeds you can
subscribe to. Runs entirely on Cloudflare Workers.

Live at <https://menu.smartcode.dk>.

This is a TypeScript rewrite of the original .NET 10 / Blazor SSR app, moved off a VPS
onto a serverless platform. The output contract is unchanged: same URLs, same event UIDs,
same menu type ids, so existing subscriptions keep working.

## Architecture

| Piece | Where |
| --- | --- |
| HTTP routing | Hono, `src/index.ts` |
| Views | Hono JSX, `src/views/` |
| Scraper | `src/scrape.ts` |
| iCal serialiser | `src/ical.ts` |
| Persistence | Workers KV, one JSON document, `src/store.ts` |
| Refresh | Cron trigger every 6 hours, `scheduled()` in `src/index.ts` |
| Static assets | Workers Static Assets, `public/` |
| Styling | Tailwind CSS v4, `styles/app.css` |

There is no database. The full dataset is a rolling two-month window over seven menu
types, comfortably under 100 KB, stored as a single KV value. The cron trigger is the
only writer.

## Endpoints

- `GET /` homepage with the calendar builder and a 7-day preview
- `GET /calendar/{menu-type-slug}.ics` feed for one menu type
- `GET /calendar/custom/{config}.ics` mixed feed, e.g. `M1T1W1R2F1` = Mon/Tue/Wed/Fri
  menu type 1, Thu menu type 2
- `GET /api/menu-types` available menu types as JSON
- `GET /robots.txt`, `GET /sitemap.xml` generated per request
- `GET /admin/refresh-menus?secret=X` manual refresh

Add `?alarm=true` to any calendar feed for a 5-minute reminder on each event.

## Development

```bash
npm install
npm run dev          # wrangler dev on http://localhost:8787
npm test             # vitest, runs inside workerd
npm run typecheck
```

The KV namespace is simulated locally by miniflare. To populate it, hit
`/admin/refresh-menus?secret=...` against the dev server with `REFRESH_SECRET` set in
`.dev.vars`.

## First-time deploy

```bash
npx wrangler kv namespace create MENU_KV      # put the id in wrangler.jsonc
npx wrangler secret put REFRESH_SECRET
npm run deploy
```

Then add a custom domain route for `menu.smartcode.dk` in the Cloudflare dashboard, and
set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as GitHub Actions secrets so
pushes to `main` deploy automatically.

## Tests

67 tests, all running inside workerd:

- `test/port-parity.test.ts` diffs the scraper and iCal output against the original C#
  implementation. `test/oracle/` is generated by `tools/PortOracleDump.cs` and is the
  authority on what the feeds must look like. **A failure here means live subscriptions
  would break.**
- `test/routes.test.ts` end-to-end route behaviour against a real KV binding.
- `test/home-render.test.ts` markup snapshot, guarding the contract between the
  server-rendered weekly preview and the client-side re-render in `public/js/menu-app.js`.
- `test/units.test.ts` scraper helpers, config codec, date maths and store merging.
- `test/golden/` are real feeds captured from the live .NET app, used to verify the
  75-octet line folding.
- `test/backfill-fidelity.test.ts` proves the recovered history in `test/vps/` regenerates
  byte-identically. It caught that `formatDescription` is not idempotent, which is why
  backfilled entries are flagged `prerendered`.

## Constraints worth knowing

- **Menu type ids are frozen.** Custom calendar URLs encode them, so renumbering silently
  changes what a subscriber receives. Id 4 is retired and must stay unused. See
  `SEED_MENU_TYPES` in `src/store.ts`.
- **Event UIDs are frozen.** Changing the format gives every subscriber duplicate events.
- **Dates are plain calendar dates**, never instants. `src/time.ts` is the only place that
  knows about Europe/Copenhagen.
- **The weekly preview is server-rendered** so crawlers see menu content. `menu-app.js`
  re-renders it on selection changes and must emit the same markup.
- A scrape returning zero menu days never overwrites good data.
- **Backfilled entries are `prerendered`.** History recovered from the retired .NET app
  (`tools/backfill-from-vps.mjs`) stores the already-rendered SUMMARY and DESCRIPTION.
  Passing those back through `cleanupTitle`/`formatDescription` corrupts them, so the
  serialiser emits them verbatim. Fresh scrapes never set the flag.
